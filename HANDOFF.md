# HANDOFF: Connection state machine (packages/protocol, issue #53)

## What was done

Added a pure, in-memory connection state machine to `packages/protocol/src/index.ts`,
alongside the existing exports (none of which were modified):

- `ConnectionState` — the four-state union type: `"idle" | "pre-claim" | "claim" | "active"`.
  No `"cooldown"` value, per ADR 0013.
- `IllegalConnectionTransitionError` — thrown on any transition not in the legal set;
  carries `from`/`to` fields.
- `ConnectionStateMachine` — a small class holding current state (`state` getter),
  `canTransition(to)` (boolean check), and `transition(to)` (mutates state or throws).
  Constructor defaults to `"idle"` but accepts an explicit initial state.

Legal transitions encoded exactly as specified in the issue / architecture.md / ADR 0013:
`idle->pre-claim`, `pre-claim->claim`, `pre-claim->idle`, `claim->active`, `active->idle`.
All other same-state and cross-state pairs (11 of the 16 total ordered pairs across the
4 states) are rejected via a thrown `IllegalConnectionTransitionError`; the machine's
state is left unchanged when a transition is rejected.

No new dependencies, no MQTT/adapter code — pure logic and types only, consistent with
the rest of the package.

## Tests

Added to `packages/protocol/test/index.test.ts`:
- One test per legal transition (5), asserting `canTransition` returns `true` and
  `transition` succeeds and updates `.state`.
- One test per illegal transition, generated by enumerating all 16 ordered pairs of the
  4 states and subtracting the 5 legal ones (11 tests), asserting `canTransition` returns
  `false`, `transition` throws `IllegalConnectionTransitionError`, and state is unchanged.
- A guard test asserting the illegal-pair count is exactly 11 (catches accidental
  enumeration bugs in the test itself).
- A sanity test that `"cooldown"` is not among the four states.
- Two smoke tests for default/explicit constructor initial state.

Ran `pnpm turbo test --filter=@thrw/protocol`: 30/30 tests pass (was 8 before this change).
Also ran `pnpm run typecheck` inside `packages/protocol`: passes with no errors.

## Uncertain / not done

- Error-vs-typed-return choice: went with a thrown error (`IllegalConnectionTransitionError`)
  rather than a typed `Result`-style return, per the issue's "your choice" language. If the
  rest of the codebase later converges on a `Result<T, E>` convention elsewhere, this may
  want to be revisited for consistency — nothing in the existing `packages/protocol` code
  established a precedent either way.
- Did not touch `NodeInterface`'s comment referencing "cooldown" as a fifth state in its
  docstring (line ~54-55 of `src/index.ts`) beyond what was already there, since the issue's
  "paths the agent must not touch" list forbids modifying `EventKind`/`NodeManifest`/etc.,
  and `NodeInterface` itself wasn't listed as untouchable but also wasn't asked to be changed.
  That comment is pre-existing and still accurate (it describes the frozen contract as not
  yet implemented "here" in the interface, which remains true — the new state machine is a
  separate, standalone export, not wired into `NodeInterface`). Left as-is; flagging in case
  a reviewer expects that comment updated to point at the new `ConnectionStateMachine`.
- No adapter wiring, no `onClaim`/`onRelease` integration with the new state machine — that's
  explicitly out of scope per the issue (adapters/relay-core are separate milestones).
