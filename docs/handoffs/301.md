# 301 — A call cannot break a wedge the re-assert bound has given up on

## What was wrong

The relay believed the Pixel held `audio`. The Pixel reported no route. The Mac
physically had the headset. #289's bounded re-assertion had spent its two
attempts and logged `reassert_exhausted`.

From that state, nothing the user could do moved the headset. Arbitration acts
on holder *changes*, and there was no change to act on: the Pixel emitted
`call`, the relay recomputed, found the Pixel already holding, and sent nothing.
Two real calls — WhatsApp and mobile — both failed.

This is the half of #289's own analysis I did not implement. #289 said the relay
should either stop believing or stop trying, but not loop forever. I built
*stop trying*. Stopping trying without stopping believing is the wedge.

## What changed

One new method, `breakWedgeForUrgentTrigger`, called from the event branch after
`syncHolder` — `services/relay-hosted/src/relay-service.ts:825`, defined at
`:1092`.

When a `call` or `manual_claim` starts on a node the relay *already* believes is
the holder, it resets `reassertsThisTenure` to 0, logs `urgent_reassert`, and
dispatches a claim immediately.

Three guards, in order:

1. `type !== "call" && type !== "manual_claim"` — `media` and `voip` are ambient
   and fire constantly. Letting them dispatch per event is how #287's fighting
   started. (`:1099`, reset at `:1104`)
2. `lastHolder !== holderBefore` — a real holder change already dispatched
   through the normal path; a second command here is the duplicate #284 is
   about. (`:1102`)
3. `lastHolder !== node` — only the believed holder can be wedged. (`:1103`)

The budget reset matters as much as the dispatch: without it the tenure stays
exhausted, and the ordinary periodic path can never help again.

## Not verified

**Nothing here has been seen on hardware.** The wedge was observed in
production logs; the fix has only been observed in tests. The thing to watch for
after deploying is a `urgent_reassert` line appearing in the relay log at the
moment a call starts on a node that is already the holder, followed by the route
actually moving.

## Uncertain

- **Why the Pixel's belief went stale in the first place is still unexplained.**
  This change makes the wedge escapable; it does not stop the relay believing
  something false. ADR 0018's periodic reconciliation from observed route is
  supposed to correct that and evidently did not, at least not before the bound
  ran out. That is worth its own issue.
- The choice to *not* let `media` break the wedge means a wedged state with only
  music playing still needs the periodic path or a node restart. That is
  deliberate, but it is a judgement call, and if the wedge turns out to be
  common it may be the wrong one.
- `services/**` is human-merge (AGENTS.md), so this PR needs review regardless
  of CI.
