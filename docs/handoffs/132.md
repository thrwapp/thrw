# HANDOFF: adapter-android applicationId decision (#132)

## What was done

Changed `packages/adapter-android/app/build.gradle.kts`'s
`defaultConfig.applicationId` from `com.thrw.adapter.android` to
`app.thrw.android`, per Tom's decision recorded on #132 - matches the
`app.thrw.mac` convention already chosen for the Mac bundle ID
(reverse-DNS of `thrw.app`, the domain thrw actually owns), made now
because `applicationId` is effectively immutable after the app's first
Play Store publish.

`namespace` (`com.thrw.adapter.android`) is deliberately left
unchanged - it controls the Kotlin package every source file already
lives under (`com/thrw/adapter/android/...`), and AGP treats it as
fully independent from `applicationId`. Renaming it would mean moving
every source file and updating every `package` declaration; nothing
about this decision required that, since `applicationId` is purely the
manifest/Play Console identity and is designed to be free to differ
from the source package.
