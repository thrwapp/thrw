# 273 — telling a machine what thrw is

#231 made the site's metadata correct. It did not make the site *legible as an
entity*: the only structured data was `FAQPage`, so a crawler could read five
answers about a product it had no machine-readable description of — no name,
no logo, no repository, no licence, no operating systems. All of that existed
only as prose.

This adds the entity layer, an `llms.txt`, and an explicit AI-crawler policy.

## What changed

**One source for facts more than one place states** —
`src/lib/site.ts`: `SITE_NAME` (`:8`), `REPO_URL` (`:10`), `LICENSE_URL`
(`:17`), `PLATFORMS` (`:31`), `andList` (`:48`), `AI_CRAWLERS` (`:70`). The
origin is deliberately *not* here: it stays in `astro.config.mjs`'s `site` and
arrives via `Astro.site` / an endpoint's `site`, per #231 criterion 4.

**`PLATFORMS` is the interesting one.** The FAQ said "Adapters for Android,
Mac, iPad, and Linux" as a hand-written string; `SoftwareApplication` needs the
same fact as OS names. Two lists would let structured data claim a platform the
page never mentions. Now one array carries both — `label` for prose, `os` for
schema — and `index.astro:38` builds the FAQ answer from it via `andList`, which
reproduces the original string byte-for-byte, Oxford comma included.

`andList` is hand-rolled rather than `Intl.ListFormat` on purpose: the output is
rendered marketing copy asserted by tests, and ICU data differences between a
laptop and a CI runner should not be able to change it quietly.

**The graph** — `src/lib/schema.ts:28` builds one `@graph` with `WebSite`
(`:40`), `Organization` (`:49`), `SoftwareApplication` (`:59`) and the existing
`FAQPage` (`:76`), cross-linked by `@id`. One `<script>` rather than four, so a
consumer reading the software node can follow `author` to the organisation
instead of inferring the relationship. Emitted from `index.astro:60,68`.

`description` is passed in rather than restated, so the graph cannot describe
the site differently to the `<meta name="description">` a few lines above it in
the same `<head>`.

**No price claim** (`schema.ts:69`). No `offers`, no `isAccessibleForFree`.
thrw is pre-launch and pricing is undecided, so "free" would be structured data
asserting something nobody has decided — the source being MIT is a different
statement to the hosted product being free. This also keeps the change clear of
anything `pricing`-shaped, which is human-merge in this repo.

**`llms.txt`** — `src/pages/llms.txt.ts`, an endpoint rather than a file in
`public/`, so its origin comes from `site` like `robots.txt` and `sitemap.xml`.
Page list from the shared `src/lib/routes.ts`, so a new page cannot go missing
from it.

**Explicit AI crawlers** — `robots.txt.ts:13` emits a group per entry in
`AI_CRAWLERS`. Behaviourally a no-op today, and the comment says so: the
wildcard already allows all of them. It buys two things — the policy becomes a
decision on the record, and if `*` ever gains a `Disallow` these agents keep
access via most-specific-wins rather than silently inheriting it.

**Full-size card** — `Base.astro:52` adds
`index, follow, max-image-preview:large, max-snippet:-1, max-video-preview:-1`
to indexable pages. The 404 still emits only `noindex`.

**`src/lib/routes.ts`** — the route glob moved out of `sitemap.xml.ts` so
`llms.txt` enumerates exactly the same pages.

## Deliberately not done

**`<lastmod>` in the sitemap** (`sitemap.xml.ts:16`). I offered this and then
rejected it, because neither available source is honest: a build timestamp
claims every page changed on every deploy, and a git-derived date depends on the
clone depth CI happens to use. Search engines discount a sitemap whose `lastmod`
they learn to distrust, so none beats wrong. Flagged rather than quietly
dropped.

**Content that would actually get thrw cited** — #274. This change makes the
site legible; it does not make it quotable. An assistant asked "how do I share
one pair of AirPods between a Mac and an Android phone" still finds nothing on
thrw.app to ground an answer in. That is writing, not plumbing.

`pnpm turbo build test typecheck --filter=@thrw/site --force` — **24 tests pass**
(18 before), typecheck 0 errors / 0 warnings / 0 hints, 0 cached.

The `--force` matters: turbo's cache is shared across worktrees, and an earlier
run in this session reported `FULL TURBO` while replaying logs from
`/Users/tmiller/Code/thrw-wt-190`. A green uncached run is the only one that
says anything about the tree you are in.

Six new tests (`test/meta.test.ts`): linked entities with no dangling `@id`
(`:108`), platform parity between schema and prose (`:134`), no price claim
(`:155`), `llms.txt` covering every sitemap route (`:167`), every AI crawler
named (`:188`), full-size card except on the 404 (`:201`).

**The platform-parity test was mutation-checked**, not just written: adding a
fifth platform to `PLATFORMS` made it fail with `meta description is missing
Windows`. Worth recording what that proved — the derived half (FAQ prose)
updated itself automatically and the hand-written half (meta description) failed
loudly, which is exactly the intended split.

Verified directly against built output: the FAQ answer is byte-identical in
`dist/index.html`, the graph parses with four nodes and no dangling references,
`operatingSystem` is `"Android, macOS, iPadOS, Linux"`, and `dist/llms.txt` and
`dist/robots.txt` contain what they should.

`content/site/test/index.test.ts` is **not** in the diff — the copy frozen by
#34 criterion 3 is untouched, and its four tests still pass.

## Uncertainties

1. **`llms.txt` has no proven reach.** It is a proposed convention and I cannot
   confirm any major assistant reads it. Justified on cost (a few generated
   lines) rather than evidence of effect, and it should not be mistaken for a
   mechanism with known reach.
2. **Explicit robots groups change nothing today.** If you would rather not
   carry 30 lines for a policy statement, the wildcard alone is functionally
   identical — the hunk is separable.
3. **Cloudflare can override all of this.** The dashboard has an AI-crawler
   block, and Bot Fight Mode can reject those agents regardless of `robots.txt`.
   Not visible from the repo, not checked, and if enabled it makes the crawler
   half of this change inert.
4. **The site claims four platforms; two are real.** `adapter-ipad` is a bare
   skeleton (#115) and `adapter-linux` is a BlueZ seam with no node interface
   (#271). This change propagates the page's existing claim into structured data
   rather than introducing it — but it does mean the overclaim is now
   machine-readable. Raised on #274; not mine to reword unilaterally.
