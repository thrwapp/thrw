# HANDOFF: adapter-android gradlew assembleDebug Netty packaging conflict (#131)

## What was done

Added an AGP `packaging { resources { ... } }` block to
`packages/adapter-android/app/build.gradle.kts` excluding two
`META-INF` files that several of `hivemq-mqtt-client`'s transitive
Netty dependencies each ship their own copy of, which AGP's resource
merger refuses to pick between without explicit guidance.

Reproduced the exact failure from the issue first (clean `main`,
`./gradlew assembleDebug`), confirming it's real and current, not
already fixed by anything since the issue was filed.

## Acceptance criteria, with evidence

**1. `./gradlew assembleDebug` succeeds.** Confirmed, from a clean
worktree with a fresh Gradle daemon (no cached task state) - see "Test
evidence" below. Two conflicts had to be excluded, not one:
`META-INF/INDEX.LIST` (named in the issue) and, once that was fixed, a
second conflict on `META-INF/io.netty.versions.properties` surfaced
(7 Netty jars this time, including `netty-common`, which doesn't ship
`INDEX.LIST` but does ship this file). The issue's own text only
anticipated the first.

Per the issue's own instruction not to assume `excludes` is safe:
checked what each file is actually for before dropping it, not just
its `INDEX.LIST`:
- `INDEX.LIST`: a JAR-indexing-era lookup optimization from the old
  `java.net.URLClassLoader` "Class-Path" mechanism (pre-JPMS). Nothing
  in Netty's runtime reads it - the JVM just falls back to normal
  classpath scanning when it's absent.
- `io.netty.versions.properties`: per-module version/commit metadata,
  read only by `io.netty.util.Version.identify()` for diagnostic
  banners. Nothing in this adapter (or `hivemq-mqtt-client`, for its
  actual connection logic) calls that API.

Both are excluded outright (`excludes +=`), not picked-first
(`pickFirsts +=`): keeping one arbitrary copy of either would give no
real benefit, since each is only meaningful paired with the specific
jar it was generated for.

**2. `./gradlew bundleRelease` also succeeds.** Confirmed - hit the
same two conflicts (release and debug share the same merged dependency
graph), fixed by the same exclusions. No release-specific packaging
issue beyond that.

**3. `./gradlew test` still passes, unmodified.** Confirmed - this
issue only touches the `packaging {}` block, nothing in `testOptions`
or the dependency graph itself.

**4. Documented (not implemented) whether `ci.yml`'s `android` job
should also run `assembleDebug`.** Yes, it should: this bug shipped
silently since #83 first pulled in `hivemq-mqtt-client` because
`ci.yml`'s `android` job only runs `./gradlew test`, which never
exercises AGP's resource-merge step at all - `test` and
`assembleDebug`/`bundleRelease` are genuinely independent task graphs
that happen to share compiled Kotlin. Recommend adding
`./gradlew test assembleDebug` (not `bundleRelease` - that needs a
signing config decision that's #132's territory, not CI's) to the
existing `android` job's run step. Per AGENTS.md, `.github/**` is
always human-merge regardless of directory, so this is left as a
recommendation here, not implemented as part of this `packages/**` PR.
