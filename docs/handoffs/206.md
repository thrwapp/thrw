# Handoff: #206 — confirmed switch outcomes (ADR 0019)

**Partial. Stage 1 (the receiver) is done; stage 2 (the adapters) is not.**
Read the "What is NOT done" section before assuming ADR 0019 is implemented.

## Why

A claim or release was fire-and-forget. The relay published a command and
never learned whether the switch happened, so "did that work?" was
unanswerable except by looking at the headset, and switch success rate —
the number that says whether thrw is reliable — could not be measured at
all, only inferred from the absence of complaints.

A full day of live debugging on the reference hardware is the evidence.
A claim the Pixel silently skipped (#244) surfaced only as a
`route_drift` two minutes later with no reason attached, and was
attributed to three different wrong causes in turn before the real one
was found by experiment.

## What landed

`packages/protocol`:

- `CommandOutcome` — `succeeded` / `failed` / `timed_out`.
- `CommandFailureReason` — a closed set (`bluetooth_unavailable`,
  `target_device_unreachable`, `superseded_by_newer_command`). Closed
  rather than free text because the whole point is to aggregate, and
  free-form strings do not group. `superseded_by_newer_command` exists
  now, ahead of ADR 0020's coalescing, so it is not retrofitted into data
  already being collected (#206 criterion 5).
- `CommandOutcomePayload` — rides the **events** topic under a `kind`
  discriminator alongside `register` and `event_end`. That is the only
  node-publishes topic in the frozen set (ADR 0001/0015) and already
  carries several kinds, so **no topic change and no flag day** — only
  possible because #171's migration (`2ab3dd6`) and the sequence/epoch
  work (#224) had already landed. `epoch` and `seq` identify which
  command an outcome answers, reusing the pair ADR 0018 point 1 added.
- `COMMAND_OUTCOME_TIMEOUT_MS = 8_000`, pinned and asserted here rather
  than per-adapter, per criterion 2.

`services/relay-hosted`: parses outcomes, reports them through
`onCommandOutcome` following `onRouteDrift`'s injectable-sink shape
(criterion 4), defaulting to the logging path #245 built. ADR 0019
explicitly sanctions this — `services/telemetry` is a placeholder, so
reporting lands first and emits into logging until aggregation is real.

### Two deliberate properties, both tested

- **An outcome never touches arbitration.** No engine call, no
  `syncHolder`. It is a report *about* a command, not a trigger. Acting
  on one — retrying a failure, correcting a timeout — is a separate
  decision ADR 0019 does not make, and a late outcome from a superseded
  command moving the holder would yank the headset back. Asserted as an
  absence-of-effect test.
- **A malformed outcome is dropped, not recorded.** Validated field by
  field rather than trusted on its `kind`, because this is the one
  payload treated as evidence about reliability. A `failed` with no
  reason is unaggregatable, so it is discarded rather than logged as a
  failure of unknown cause that quietly skews the success rate.

## What is NOT done

- **Stage 2: the adapters.** `NodeInterface.onClaim()`/`onRelease()` are
  still fire-and-forget. No adapter reports an outcome, so **nothing
  populates this yet** — the relay is a tolerant receiver with no
  senders. Criteria 1, 2 (the enforcement half), 3 and 6 are all
  outstanding.
- **Criterion 5's emission point.** The reason code exists; nothing emits
  it, because ADR 0020's coalescing is not implemented.
- **Criterion 6** — the interaction with #191's in-flight suppression is
  unaddressed, and belongs with stage 2 where the outcome is actually
  produced.
- **No hardware verification.** Nothing to verify until adapters report.

## Sequencing note for whoever picks up stage 2

**Do #244 first.** ADR 0019 will *report* a silently-skipped claim;
#244 is what stops it happening, and it is a much smaller change.
Reporting a bug you could instead fix is the wrong order if only one gets
done.

Stage 2 is a frozen-contract change (the node interface), so it is
human-merge per AGENTS.md, and it spans Swift and Kotlin plus a reinstall
on both reference devices to verify. The 8s bound must come from
`COMMAND_OUTCOME_TIMEOUT_MS`, not be re-typed per platform — there are
three hand-written implementations of this contract and nothing else
catches them drifting.
